# Split workspaces, overlay collaboration and compact Settings

Workspaces supports single view, Split right and Split below with a draggable/keyboard-resizable divider. Pane headers choose the workspace. The workspace list targets the focused pane; its other-pane button opens a workspace in the other pane. Selecting an already visible workspace focuses its existing pane instead of creating a second editor. Single view retains the focused workspace and does not delete content. Each workspace has one persistent view/engine. Paint iframes remain body-level portals; only their placeholder geometry changes. Canvas DOM views may move but are not recreated. Settings switching preserves workspace runtime state.

Each workspace view has an independent right-hand overlay drawer, not a layout column. Chat shows User messages on the right, Agent messages on the left, date separators, reply quotes, a bottom composer and a new-message jump button. Loading older messages preserves scroll position. Replies outside the loaded range can be fetched and located. Agent activity uses compact cards with author, tool and time; the magnifying glass opens saved Input/Output summaries in a dialog. No raw tokens or full image payloads are added to logs.

Collapsed drawer buttons show unread non-User message counts (99+ display cap). Unread is cleared only through the latest actually rendered messages when the workspace, Chat tab and document are visible and the user is at the bottom. A hidden workspace gets a list red dot for new messages, tool record updates or persisted content revision changes. Both split panes count as visible; Settings or a hidden browser document counts as not visible. Opening workspace content clears its generic update dot, not necessarily the Chat unread count. Start/finalization states share one activity record. First initialization baselines pre-existing history rather than fabricating a backlog. Read watermarks are localStorage-only; existing messages/logs are unchanged. Manual in-memory drawing/animation without a persisted revision or tool call is not separately tracked.

Settings normal rows are single-line. Agent state is an accessible colored dot; IDs truncate visually with full value in the tooltip and existing copy controls. System Activity has separate Agent ID and inline status light by tool name. Tool descriptions are one-line summaries with explicit expandable full text. Expanded details are allowed to be multiline. All Settings table pagination and filtering remain. Token controls and lifecycle are unchanged.

No browser session, relay changes, automatic test workflow or cloud deployment are included. Existing workspace/token/history keys are preserved; the additional read-marker key is web-mcp-poc.workspace-read.v1. Local unread/draft state is not cross-device sync. Browser acceptance, split geometry, iframe focus, overlay stacking, notification timing and compact responsive tables require manual verification; no pass is claimed for this source change.
